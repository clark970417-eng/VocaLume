# VocaLume 4.6.0 quality evaluation status

[Home](../../README.md) · [Evaluation procedure](README.md) · [Recorded measurements](4.6.0/interrupted-soak-summary.json)

**The long-session qualification was stopped at the user's request because the computer became sluggish. It did not pass the one-hour completion gate. No further local tests were started.**

## What was recorded

| Item | Result |
| --- | --- |
| Device | Apple M5, 16 GB RAM, macOS 26.4.1 |
| Input | One authored synthetic Japanese clip, repeated at real-time pace |
| Last saved checkpoint | 46.15 minutes; 209 of 274 planned rounds |
| Completed final-caption jobs | 419 of 419 recorded final decodes |
| Blank final outputs / recorded pipeline errors | 0 / 0 before stopping |
| Capture-window end to translation, p50 / p95 / p99 | 0.95 s / 4.20 s / 9.16 s |
| Slowest recorded caption | 15.83 s |
| Thermal state reported by the test | `fair` |
| Result | Interrupted and incomplete; not a stability or speed qualification |

The long tail and the user's report of sluggishness must remain visible. The absence of recorded pipeline errors does **not** mean the experience was smooth.

This run was not an idle-machine benchmark. Normal desktop use continued, and repository builds and lightweight checks also ran. A late snapshot showed substantial swap usage and system load; it cannot establish which activity caused the slowdown. No second model benchmark ran concurrently. Parent-process memory measurements in the JSON do not include the full recognition process or GPU memory.

The repeated input benefited from translation caching. Silero probabilities were computed before replay, so these timings exclude live VAD computation, browser/microphone capture and rendering. They are not complete speech-to-screen latency measurements or an uncached translation benchmark.

The summary retains the local raw report's SHA-256. The interrupted raw checkpoint remains local; it has not been relabeled as a completed run.

## Ready, but not yet measured or reviewed

- The frozen corpus defines 28 audio cases: 14 Japanese-to-Chinese and 14 Chinese-to-Japanese, plus 8 Japanese context cases. Audio hashes were recorded before measurement.
- The new bilingual model run was **not started** after the user asked to stop testing. There is no new accuracy result from that corpus.
- Bilingual human review, real multi-speaker recordings, a completed 1–2 hour varied-content session, and other physical Mac/Windows devices remain pending.
- Gemini request/response handling was checked locally; no real paid Gemini request was made. Account access, quota and model availability remain unverified.

Before testing was stopped, the source checks had passed: 250 extension tests, the previously completed 832 desktop tests, clean-checkout builds, and 5 native bridge checks. These are software regression checks, not human translation-quality evidence.

The published 4.6.0 release remains an unsigned Beta. This record makes no claim of improved speed, a translation-accuracy percentage, or completed commercial qualification.
