# VocaLume 4.5.7 — recoverable translation failures

2026-10-26. Baseline: `3c2b642bc15db34c5c6cda129ddab9a261c7e9f3` (4.5.6). Apple M5, 16 GiB, macOS 26.4.1; existing HY-MT1.5-1.8B Q4_K_M model. [Inputs, outputs and timings](4.5.7-measurements.json).

## Reproduced failures and changes

1. A multi-line Japanese/Chinese message was split into smaller requests. A standalone emoji, date, URL or handle could return unchanged, fail the target-language check, and reject the entire message. Preserve literal-only chunks without inference. Ordinary words, including Han-only Japanese, still use the translation route. Returning an emoji or URL instead of a real sentence still fails validation. The desktop shortcut also honors cancellation and explicit personal glossary overrides.
2. Japanese → Chinese page reading called the caption translator without its requested pair. If speech was set to Korean → English, the page could use that pair too. Pass the reading pair explicitly and keep the caption default for speech callers. Both cases failed before the production fix and passed afterward in the full-background regression harness.
3. A temporarily full local text queue was not retried by the native client. Retry once after 400 ms, only within the original overall deadline and only for stateless text/settings requests. Keep the same native port. Audio and capture controls are never replayed by this path; existing disconnect recovery remains bounded.
4. After one failed page retry, the status required refreshing the whole page. YouTube and social adapters now offer **再試一次** on that row. The automatic retry remains bounded; DOM mutations cannot cause an endless retry loop. The button checks current text, language settings, opt-in state and ownership before submitting. X already has an explicit reusable translation button and uses the shared background fixes.

Capture waiting, VAD/silence thresholds, recognition settings, models and translation sampling are unchanged. No extra model correction pass is added. A delayed retry applies only to an already-failed text request, not microphone buffering.

## Real-model check

The [nine-case corpus](../../extension/tests/fixtures/translation-recovery-4.5.7.json) is authored regression material, not copied user messages or a blind benchmark. The frozen baseline and candidate each ran once against the same local model in an isolated profile. The harness uses the production chunker, translation policy and local engine, sequentially; it excludes browser/native IPC, audio, recognition, normal background concurrency and rendering.

| Selected check | 4.5.6 | 4.5.7 |
| --- | ---: | ---: |
| Mixed prose and literal-only lines | 0 / 5 | 5 / 5 |
| Standalone emoji/date unchanged | 0 / 2 | 2 / 2 |
| Ordinary Japanese/Chinese prose controls | 2 / 2 | 2 / 2 |
| All selected checks | 2 / 9 | 9 / 9 |

For `今日は楽しかったです。` followed by separate emoji, date and URL lines, the baseline raised `翻譯服務未回傳繁體中文`; the candidate returned the Chinese sentence with all three literal pieces intact and made one model request. Both ordinary prose controls retained the same output in both versions. All five mixed cases now require one model request for the prose; the standalone literal cases require none. The results establish these specific fixes, not general translation accuracy or a faster end-to-end speech benchmark. Existing chunk joining is unchanged.

No live-site or GUI completion is claimed while this check is pending.

## Limits

Network outages, unavailable models, invalid model output and a persistently overloaded device can still fail. The UI offers a deliberate retry instead of claiming a missing or invalid translation succeeded. This patch does not change recognition accuracy or resolve every possible audio-service failure.

Source/local version is 4.5.7. Public preview installers remain 4.4.5 and are not relabelled by this update.
