# VocaLume 4.5.4 — background audio and conservative tense repair

2026-10-25. Baseline: `e3dbff53d1c6336cf22f048db197b8e80538c48e` (4.5.3). Local checks use an Apple M5 with 16 GiB on macOS 26.4.1, existing MLX Whisper large-v3-turbo and HY-MT1.5-1.8B Q4_K_M. No cloud translation or replacement model is required.

## Background audio

4.5.3 logged audio-helper watchdog restarts, sometimes approximately four minutes apart. The main app survived. A sampled helper was mostly idle; a separate normal desktop launch kept the same helper alive for more than six minutes. These observations do not establish a universal CoreAudio deadlock or a single cause.

This patch removes unnecessary desktop audio startup from the browser-companion path:

- Browser-only companion launches defer the desktop windows. On macOS they start as an accessory; requesting desktop settings restores ordinary app activation. Desktop capture, explicit settings and normal desktop launches retain their UI.
- Saved TTS / virtual-microphone settings retain hidden playback windows. Translation does not silently disable these features.
- Device discovery no longer briefly opens a microphone on mount. Only an actual capture request asks for microphone access; labels refresh after permission is granted. Device changes refresh the list without replacing a selected device.
- The original microphone stream is retained for cleanup, including failures while setting up noise suppression or VAD.
- Capture shortcuts open a deferred desktop UI before requesting capture and cannot interrupt an active browser capture session.

Electron is updated from 33.4.11 to 44.9.3. The native-build ABI registry and NAN headers are refreshed within their existing dependency ranges. The macOS system-audio usage description is included. The app keeps its existing permission checks, sandbox settings and watchdogs. Electron's [supported release policy](https://www.electronjs.org/docs/latest/tutorial/electron-timelines) and [activation API](https://www.electronjs.org/docs/latest/api/app/#appsetactivationpolicypolicy-macos) document the runtime and activation behavior; they do not prove this particular audio issue is fixed.

## Translation checks

The [32 authored cases](../../tests/fixtures/tense-4.5.4.json) were frozen before the production correction. [Outputs and measurements](4.5.4-measurements.json) retain both versions' text.

The original failure, `今天沒辦法看到最後，明天再來看！`, produced `今日は最後を見ることができませんでしたが、明日また見に来ます！`. It now produces `今日は最後を見ることができませんが、明日また見に来ます！`, retaining current inability rather than an invented past event. The other 31 outputs are unchanged.

The correction is intentionally narrow: explicit current/future Chinese time, one inability clause, and a Japanese negative-past ability form. Past evidence, quoted language, conditions, questions, uncertain polarity and multiple inability clauses prevent rewriting. Japanese conditional `なかったら` and listing `なかったり` are preserved. No extra model pass is added. This does not repair arbitrary grammar or missing acoustic evidence.

| Sequential local text sample | 4.5.3 median | 4.5.4 median |
| --- | ---: | ---: |
| Chinese → Japanese, 18 cases | 398 ms | 456 ms |
| Japanese → Chinese, 14 cases | 252 ms | 283 ms |

These samples include a runtime change and do **not** establish faster translation. A shorter-prompt experiment also failed to repair the tense error and changed some meanings, so it was discarded. The production prompt and model settings remain unchanged.

Real Silero / ASR / translation processed three paced repetitions of the existing authored speech fixture, about 39.75 seconds total. All six final captions included Chinese; none were empty. Each repetition retained the fish clause with `しまいました` and a completed Chinese event. This is a controlled regression check, not an accent or live-stream quality score.

The run made 39 ASR calls (18.98 s cumulative) and three model translations (0.88 s cumulative, with existing caching). Median final-audio-end to Chinese completion was 694 ms. The previous later 4.5.3 run measured 622 ms with 36 ASR calls; cadence and cache hits differ, so this is a functional check and does not establish an end-to-end speed gain. Capture waiting, silence thresholds, audio-window bounds and model selection are unchanged. No new correction inference is added.

## Verification and installation

- 803 desktop tests in 83 files, 192 extension tests and five Python bridge tests passed. Type checking, production build and packaging passed. Lint has zero errors and the same 16 existing warnings.
- Regression tests cover deferred settings/playback windows, a single audio-port listener, reopening after closure, browser-capture protection and tense guards.
- Native addons rebuilt for Electron 44.9.3. The packaged runtime, bridge scripts, VAD/renderer assets, portable addon paths and local ad-hoc signature were verified. The installed app is 4.5.4 with the original icon; settings, models and the previous 4.5.3 app are retained.
- The installed app's local companion protocol confirmed no desktop/settings window, no subtitle window and no active capture at background startup. An Electron renderer process remained present; this alone is not evidence that desktop windows were opened. No audio-service or video-capture helper was present. An authored Chinese draft returned the corrected non-past Japanese; authored Japanese audio returned a complete Chinese result, and Stop completed in approximately 0.5 s. These are backend checks, not browser tab-capture checks.
- Extension source/manifest is 4.5.4. Opera GX reload, actual tab capture, microphone/system-audio permissions and overlay behavior for this version are **postponed at the user's request**. No Opera UI operation is included in this patch's verification. Earlier 4.5.3 browser checks do not verify Electron 44 capture or extension 4.5.4.

Public preview download assets remain 4.4.5. This source/local-app update is not Apple Developer ID signed or notarized and does not claim full cross-device or live-site qualification.
