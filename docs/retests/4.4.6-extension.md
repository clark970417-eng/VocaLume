# Discord browser patch 4.4.6

2026-10-20, Asia/Taipei. Desktop remains 4.4.5: no desktop code/model changes.

## Change

Discord now uses a dedicated adapter selecting complete `[id^="message-content-"]` bodies. It does not translate channel headings and does not use generic live-region leaf scans that can include usernames, badges or announcements. The current reading language is respected. Multi-line messages are sent as one body, with whitespace normalized as in the existing social adapter.

## Verification

- 159 extension tests passed, including authored Korean multi-line body coverage, exclusion of heading/live-region scans and respecting an explicitly selected Japanese source.
- Reloaded the actual Opera GX unpacked extension; extensions manager showed 4.4.6.
- Refreshed the user's existing Discord web tab. Its reading setting had been Japanese while the requested messages were Korean. Selected Korean → Traditional Chinese; synchronized typing became Chinese → Korean, while speech stayed Japanese → Chinese.
- Observed seven translated message rows, zero retry/failure rows in the final accessibility snapshot, and an unchanged channel heading. No message was sent.
- Private channel identifiers, usernames and message contents are intentionally omitted from this public report.

## Limits

This verifies message-body discovery and placement on the current Discord web page. Translation quality remains dependent on the chosen engine; some Korean wording was poor. Native Discord desktop apps are outside the browser extension. Other reading languages must still be selected in the popup; source language is not automatically inferred for each message. Existing public 4.4.5 release archives are unchanged; this browser patch is in the repository and installed unpacked extension.
