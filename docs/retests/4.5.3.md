# VocaLume 4.5.3 — recognition work, vocabulary and memory pressure

2026-10-25. Apple M5, 16 GiB, macOS 26.4.1. Baseline: `c899041340781361675021e5078a77d7c4e2340d` (4.5.2). Same local Whisper large-v3-turbo and HY-MT1.5 models. No cloud service or new model download is required.

## Changes

- Reuse an identical recognized PCM window within the same cue. Growing windows still require unchanged speech evidence, an identical PCM prefix and quiet added frames. An earlier unpadded result additionally needs two actual matching recognitions; cached results do not count toward this two-recognition requirement. Changes to cue, engine, language, glossary or source context invalidate reuse.
- Give explicit Japanese MLX/Kotoba recognition a bounded vocabulary: at most eight terms / 128 characters, with personal vocabulary and relevant streamer/game names. Built-in terms are selected from the current cue's recognized Japanese, not the previous Chinese translation or another cue. Auto-detected and non-Japanese recognition remain unprompted. This improves spelling in some cases; it is not a general accuracy guarantee.
- Transfer short audio as in-memory PCM16 instead of a temporary WAV. The samples are byte-identical to the previous transport. Large inputs keep the WAV path; invalid payloads are rejected before inference.
- Sample actual macOS memory pressure asynchronously while audio is active. Windows uses available system memory; Linux uses `MemAvailable`, not the smaller `MemFree`. Unknown sensors stay unknown. High pressure reduces optional draft work; critical pressure pauses drafts. Accepted final sentences remain in order and still translate. Existing temperature and CPU-speed protections take precedence when stronger; recovery remains gradual. Accumulated swap size alone does not trigger throttling.
- Advanced extension diagnostics now show memory pressure alongside the existing performance status.

`streaming.mjs`, `sentence-boundary.mjs`, `preview-budget.mjs`, `offscreen.js` and `vad-worker.js` are unchanged from 4.5.2. Capture wait, silence thresholds, audio bounds, selected model and translation settings are unchanged. No second correction inference was added.

## Real-model checks

[Measurements](4.5.3-measurements.json) contain outputs and timings. The [six authored recognition cases](../../extension/tests/fixtures/ja-recognition-vocabulary-4.5.3.json) were frozen before runtime changes; their audio was synthesized with macOS Kyoko at rate 180 and converted to mono PCM16 / 16 kHz. The creator name uses the explicit kana pronunciation in `spoken`. The corpus harness supplies the listed personal vocabulary to the candidate. These are controlled checks, not live-stream, accent or general accuracy scores.

| Case | 4.5.2 recognition | 4.5.3 recognition |
| --- | --- | --- |
| Creator | コンマホ、カノマホロー | コンまほ、鹿乃まほろ |
| Shooter | バンダル | ヴァンダル |
| Pokémon, negative command, schedule, fish | Complete source meaning retained | Same source meaning retained |

The greeting still mixes katakana and hiragana. The negative examples retained `押さない`, `右ではなく左`, `まだ設置しません` and `配信しません`. Single-pass recognition medians were 382 ms before and 407 ms after; this does **not** establish faster raw model inference. Vocabulary hints do not add capture waiting, but their computation is not free.

The paced caption harness uses real Silero, recognition and local translation with the existing authored `tests/japanese-fixture.wav`, played three times. Each run contains approximately 39.75 seconds of paced audio and yields six final captions.

| Run | ASR calls / cumulative time | Final translations | OS temperature |
| --- | --- | --- | --- |
| Baseline first | 60 / 23.22 s | 6 complete, 0 empty | nominal |
| Candidate first | 54 / 21.26 s | 6 complete, 0 empty | nominal |
| Baseline later | 46 / 20.23 s | 6 complete, 0 empty | nominal → fair |
| Candidate later | 36 / 14.91 s | 6 complete, 0 empty | fair |

Nominal-run median final-audio-end to Chinese completion was approximately 395 ms before / 435 ms after; the slowest captions were about 1.03 / 1.08 seconds. Reduced draft work is visible, but these runs do **not** establish a consistent end-to-end speed improvement. Warming changes preview cadence, cue boundaries and exact-cache hits, so the later runs are functional checks rather than comparable speed measurements. Two scheduling-overlap runs and the pre-final transport prototype are excluded from the saved measurements.

All runs retained the fish clause and thanks across the final captions. The existing first-run ASR tense error (`しまいます` for spoken `しまいました`) remains; no claim of perfect recognition or translation is made. Memory pressure is unknown in this isolated harness because the sensor belongs to the installed main-app lifecycle; its critical-pressure behavior is separately tested with three ordered final translations.
