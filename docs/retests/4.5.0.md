# VocaLume 4.5.0 verification — 2026-10-25

Tested on the user's Apple M5 Mac, 16 GiB memory, macOS 26.4.1. The local desktop app and unpacked Opera GX extension use 4.5.0. Public preview installers remain 4.4.5; local ad-hoc signing is not Developer ID signing or notarization.

## Changes checked

- Reuse a recognition checkpoint only when speech identity, last speech sample, PCM prefix and trailing silence agree. New or changed speech forces recognition.
- Use a shorter complete-sentence pause only with current acoustic coverage. Hanging Japanese/Chinese clauses retain the conservative pause; existing audio-window limits remain.
- Prepare stable, complete local JA/ZH translations when resources permit. Match the exact text, language, engine and glossary before reusing a result. Stop/correction invalidates preparation. The existing serial SimulMT path also receives this optimization.
- Slow optional previews when measured inference time or OS thermal pressure rises. Preserve final translations; optional acoustic tone analysis yields first.
- Expand vocabulary from 78 to 244 pairs plus the spoken ヴァロラント alias. Keep personal terms, bounded hints and context checks. Exact greetings bypass the model without replacing fragments in longer sentences.
- Add optional punctuation/laughter styling: off, natural, ww, 笑, 草. Marker decoration is excluded from context, caches and TTS. Mac acoustic classification runs locally and does not delay a late caption.

## Sustained caption continuity

[Condensed measurements](4.5.0-soak.json): 138 paced repetitions of the same authored Japanese fixture, **30 min 28 sec**, 905 ASR calls, **276 non-empty final translations**, no emitted error/fatal failure. Every round-end queue snapshot was zero and the session drained.

Only six translation calls reached the model because repeated text reused cached translations. This validates sustained audio/recognition/caption delivery, **not** 30 minutes of unique uncached translation or semantic completeness. The run preceded the final phrase-hint and TTS/pure-laughter presentation changes; those were checked separately afterward. Browser playback and desktop activity were not isolated; an installed-app microphone session was found active near the end and stopped.

End-of-captured-window to Chinese: median **1.32 s**, p95 **3.01 s**, max **6.43 s**. This excludes the pause used to close the window. First 20 median 1.95 s; last 20 median 1.24 s. These observations do not establish a speedup over the prior release. Main-process RSS was 44.2 MiB at the first sample and 36.0 MiB at the last, maximum 44.8 MiB; model subprocess memory is excluded.

All sampled OS thermal states were **fair**, speed limit 100. Acoustic laughter analysis therefore yielded to captions. No temperature in degrees Celsius was measured, and this run does not prove that the computer cannot overheat.

## Translation fidelity checks and a reproduced fix

[Eleven actual HY-MT 1.5 worker outputs](4.5.0-ja-zh-quality.jsonl) cover JA→ZH and ZH→JA greetings, negation/time, Pokémon evolution and shooter terms. Standalone known greetings used the exact-phrase shortcut; other warm calls took approximately 0.51–1.04 s in this small run. Draft fidelity handling was enabled for ZH→JA.

The first Opera test exposed a semantic omission even though its non-empty-output check passed: `魚が逃げてしまいました。来てくれてありがとうございます。` became only `謝謝您的到來。`. This was reproduced through the actual model worker. Full greetings were being provided as terminology hints. Removing those hints from longer inputs produced `魚兒逃走了。謝謝你們的到來。`; the standalone shortcut remains. The fixture now rejects this missing fish clause instead of counting any Chinese text as success.

The same checks caught a phonetic translation of ヴァロラント. Its source alias now supplies the localized title 特戰英豪. Pokémon names and the direction of evolution were retained in these examples. Some wording remains literal; these eleven cases are not a blind accuracy evaluation or a guarantee against omissions in arbitrary speech.

A separate single-pair test exposed the newly added greeting guidance being copied into a fragment translation. That prompt rule was removed; the conservative source-aware output repair remains. The fragment `しまいました来てくれてありがとうございます` no longer copied instructions in the worker check, but its output still added unsupported wording about time. This is an unresolved **model fidelity limitation for isolated cut-off fragments**, not a passing semantic-quality case. A future boundary/context improvement should be measured on such cases; this report does not hide it behind a non-empty-output result.

## Opera GX and installed-app checks

Performed in the installed Opera GX through the visible UI, using the actual native host and `/Applications/VocaLume.app`, not a mocked translation service. No social messages were sent. Test-only tabs were closed afterward.

- **Four-pair history:** six continuous fixture repetitions, 12 completed cues; the final display retained four pairs. The added fish-clause omission check passed after removing phrase hints.
- **Single-pair mode on the final package:** six visible updates; the first Chinese result appeared before the next source replaced it. Both finalized cues contained Chinese, the known instruction-copy pattern was absent, and the overlay cleared after its deadline (101 ms observed polling drift).
- **Local ZH→JA draft:** completed in 3.326 s with voice capture remaining stopped. Output: `今日は最後を見ることができませんでしたが、明日また見に来ます！`. This is a bridge/flow check; tense and style still depend on context.
- **Settings/UI:** version 4.5.0 visible; desktop local-model mode selected; `ww` retained after reopening. The speech-tone controls expand below the primary start action so adding them does not push Start beneath the initial popup view. Browser-only mode disables this desktop feature. Standalone laugh styles also pass the extension language validator only for explicit nonverbal-only input.
- **Desktop launch:** installed app opened to `Engine ready`; local model choices and the original app icon were retained. Both test captures stopped and restored caption settings.

## Limits

This report does not establish compatibility on every device, microphone, accent, stream or operating system. There was no physical Windows/Intel-Mac test. Acoustic laughter is Mac-only, conservative and can miss quiet laughter or mark background laughter. Exclamation/question punctuation follows recognized text; the feature does not infer emotions from volume. See [speech tone](../speech-tone.md).
