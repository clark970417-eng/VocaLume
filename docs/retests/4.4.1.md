# VocaLume 4.4.1 verification — 2026-10-18

## Scope

Local Mac with Apple M5 and 16 GB RAM. These results do not establish performance on other hardware, operating systems, every live site, or all Japanese accents.

## Automated and package checks

- Extension: 137 tests passed, including breathing-pause merging, late/out-of-order caption completion in single-pair mode, four-entry order, X Tab insertion without posting, stale app paths, and inaccessible model-cache recovery.
- Desktop: 673 tests passed; TypeScript checks and production build passed.
- Lint: no errors (existing warnings remain).
- The installed macOS package contains the tested main process, translator worker, preload, renderer, native dependencies and VAD resources. Deep local code-signature verification passed. This is local signing, not Apple Developer ID notarization.
- Opera GX's existing unpacked extension was reloaded and visibly reported 4.4.1 under its existing extension ID.

## Installed native transport and actual models

The test used the registered native-messaging launcher and `/Applications/VocaLume.app`, including automatic app startup. It did not bypass the relay with a direct engine mock.

- 22 requests succeeded: two written translation directions, capture initialization, 18 decode calls (six utterances, two previews plus one final each), and stop/drain.
- Every final decode returned both Japanese and Traditional Chinese.
- Each utterance used the repository's 10.722-second Japanese WAV fixture. Final request round-trip median was 721 ms across six runs. This excludes audio acquisition, sentence-end waiting, display dwell and cold initialization; repeated audio also benefits from translation caching. It is not an end-to-end live-caption latency claim.
- The OS reported `fair` thermal state, and the companion reported a 900 ms preview floor. Simulated serious/critical and CPU speed-limit changes are covered by tests. No claim of eliminating heat or proving multi-hour thermal stability is made.
- A stale executable registration and an unavailable external Hugging Face cache were reproduced. VocaLume's working registration and app-specific local Whisper cache were restored. Global external-cache symlinks were preserved.

## Opera end-to-end checks

The installed 4.4.1 app and reloaded 4.4.1 extension completed a real tab-capture test: six continuous repetitions of the Japanese fixture, separated by pauses, produced both source and translated captions. The final overlay retained exactly four groups and stopped capture successfully.

The first source draft appeared 2.33 seconds after playback began; the first full Chinese translation appeared at 19.06 seconds for a 10.722-second fixture. This includes recognition, sentence-end detection, queuing and translation. It is deliberately reported separately from the much shorter native final-request timing above. Longer inputs, heat and sustained recognition still increase latency.

A written-draft request in Opera took 24.839 seconds on the old idle 7B preference and 7.985 seconds after a fresh launch using the fast caption-model preference. These are individual cold-start observations, not a controlled speedup benchmark. The fast output had a tense error; the quality option remains available, and neither output is automatically posted. The default fast path does not start speech capture.

Single-pair late/out-of-order completion and retention passed automated tests. A separate Opera single-pair UI run was not completed because the user was concurrently operating the browser.

The existing Dock shortcut was repaired from the deleted Japanese Live Translate path to `/Applications/VocaLume.app`.

## Japanese / Chinese translation comparison

The existing 31-case bilingual corpus was run through real local HY-MT1.5 1.8B Q4 and Hy-MT2 7B Q4 workers. The small model remains the live-caption choice; written drafts default to the same caption model. The extension offers a quality option using the saved draft model while idle, without displacing an active caption model.

The corpus is a diagnostic sample, not a blind quality score. Longer generic instructions caused regressions, so the existing measured Japanese-to-Chinese prompt was retained. Improvements instead target full-sentence input, explicit writing register, context-qualified terminology, and avoiding repeated provisional translation. Explicit library/document contexts no longer have ordinary archives or paper clippings rewritten as livestream vocabulary.

Remaining model limits include implicit subjects, colloquial encouragement and tense in short Chinese messages. Model output still needs review before posting. The extension never submits a message automatically.
