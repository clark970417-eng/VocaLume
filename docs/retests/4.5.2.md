# VocaLume 4.5.2 — short Japanese without added capture wait

2026-10-25. Apple M5, 16 GiB, macOS 26.4.1. Baseline source: `97a4ca30e912edb1529aaa0eeb045ec6c72c4424` (4.5.1). Production HY-MT1.5 local worker, unchanged model and generation settings.

## Change and latency budget

- A small exact-match allowlist returns standalone greetings, thanks, requests to wait and explicit short questions before local model inference. It preserves punctuation, honors custom terminology and cancellation, and never substitutes inside a longer sentence, quotation or name. Ambiguous replies such as `はい`, `大丈夫`, `いいです` and `やばい` are excluded.
- Elliptical time questions retain the open predicate (`ところで、明日は？` → `對了，明天呢？`). An isolated `ません` only establishes negation, so the fallback is `不……`, not a guessed verb. Full recovered verbs do not match the fragment rule.
- Adjacent source recovery now covers colloquial negative endings, contractions, quoted speech and selected adjective/intent endings. Broader joins require explicit contiguous capture-cut evidence; the existing 120-character prior-clause limit, speaker/language checks, overlap checks and resets remain. No generated Chinese becomes source context.
- `streaming.mjs`, `sentence-boundary.mjs`, `preview-budget.mjs`, `offscreen.js` and `vad-worker.js` are unchanged from 4.5.1. No new capture wait, silence threshold, preview interval, timer, larger model or second inference pass was introduced. The existing 8-second normal / 12-second unfinished-cue ceiling is retained.

## Paired real-model measurement

The [38 authored cases](../../extension/tests/fixtures/ja-short-low-latency-4.5.2.json) were frozen before changing runtime code. Live voice capture and page text translation were temporarily stopped; measurements ran sequentially without concurrent builds or a second active translator. Each fresh worker loaded and warmed the same model. Run order: baseline, candidate, candidate repeat, baseline repeat. Each version produced 76 non-empty results and zero request errors.

Raw [baseline](4.5.2-before.jsonl) and [candidate](4.5.2-after.jsonl) results include source, resolved source, output and elapsed time. These measure the translation call only, **not speech-recognition, browser transport or end-to-end caption latency**. Existing exact-request caching remains enabled; repeated fragments in a run may hit it. This is a focused diagnostic corpus, not a blind accuracy score or a representative distribution of live speech.

| Group | Requests per version | Baseline median / p95 | Candidate median / p95 |
| --- | ---: | ---: | ---: |
| 14 explicit/open short replies × 2 runs | 28 | 93.18 / 199.35 ms | 0.02 / 2.36 ms |
| 9 continuation examples × 2 | 18 | 72.38 / 146.01 ms | 192.44 / 231.23 ms |
| Longer, ambiguous and unrelated guards × 2 | 26 | 128.71 / 295.01 ms | 120.64 / 288.84 ms |
| ZH→JA negation/time regressions × 2 | 4 | 379.07 / 519.25 ms | 361.03 / 502.08 ms |

The continuation group takes more inference time because it now translates the actual recovered clause instead of an isolated ending; some baseline endings also reused an incorrect cached fragment. Its median difference is about 120 ms in this run. The short-reply gains do **not** imply all captions appear in 2 ms. Guard-group timing differences are not evidence of a speed change.

## Meaning review

Eight continuation examples recovered previously missing actions/negation; one (`まだ終わって / ません`) was already handled in 4.5.1. Representative outputs:

| Input already heard | Baseline fragment output | Candidate output |
| --- | --- | --- |
| `まだ食べて / ないです。` | 沒有啊。 | 還沒有吃呢。 |
| `セーブを消しちゃ / った。` | 嗯。 | 我把存檔刪掉了。 |
| `買うつもり / はありません。` | 沒有這樣的東西。 | 我並沒有購買的意圖。 |
| `今日は来ないって / 言っていました。` | 他說了這些話。 | 他說今天不會來的。 |
| `そんなに難しく / ないです。` | 沒有啊。 | 其實並沒有那麼難啦。 |
| `ところで、明日は？` | 對了，明天是什麼日子呢？ | 對了，明天呢？ |
| orphan `ません。` | 不需要了。 | 不…… |

The orphan fallback preserves uncertainty rather than claiming a complete translation. Existing ambiguities are not solved: standalone `やばい` still comes back as `糟了`, and the model's `明日は何曜日？` output still contains the incorrect `週一`. An unusual name containing `ありがとう` is correctly excluded from the shortcut but can still be mistranslated by the model. The two ZH→JA outputs retained negation and time. These findings must not be reported as perfect accuracy.
