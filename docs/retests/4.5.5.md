# VocaLume 4.5.5 — measured local speech improvements

2026-10-26. Baseline: `e9a7d016a2ec166748f3e88417dc4386d5f7c52d` (4.5.4). Apple M5, 16 GiB, macOS 26.4.1; MLX Whisper large-v3-turbo and HY-MT1.5-1.8B Q4_K_M, existing Q8 KV cache. Models and translation sampling settings are unchanged. [Measurements and before/after outputs](4.5.5-measurements.json).

## Baseline and scope

- The [authored corpus](../../tests/fixtures/speech-quality-4.5.5.json) was frozen before implementation: eight Japanese and eight Chinese audio controls, the same 16 text controls, and eight context sequences. Audio is synthesized locally with Kyoko/Meijia; generated files have SHA-256 hashes. Context sequences use scripted recognition with the real translation pipeline/model. They do not test acoustic context recognition.
- The actual Silero/recognition/translation pipeline also processes the existing 10.7-second authored Japanese fixture at real-time pace. A fixed-cut mode disables adaptive text hints, allowing comparison of identical final capture positions. Existing translation caching remains enabled.
- Twenty-eight artificial cuts at 55% and 75% of 14 clips exercise short endings. These diagnostic cuts bypass natural VAD and include much shorter windows than ordinary streaming. Both groups were used during development; neither is a blind holdout set.
- Regex meaning checks catch selected regressions, not general translation correctness. Raw character error rate also counts Japanese spelling and Simplified/Traditional Chinese differences. Neither metric should be advertised as a product accuracy percentage.

## Changes, in implementation order

1. **Less unnecessary recognition work.** For explicit Japanese/Chinese inputs of at most 12 seconds, MLX skips unused timestamp decoding. Other languages and long file inputs retain their previous path. Punctuation-only hypothesis revisions can now satisfy quiet-tail agreement; PCM equality, speech metadata and every new quiet frame still have to pass the existing reuse checks.
2. **Protect very short endings after a forced cut.** Only an adjacent final fragment of at most one second can reuse up to two seconds of already captured audio. This uses the same final recognition call and never waits for new audio. Natural pauses, missing/invalid metadata, language changes, seeks and earlier completed sentences prevent reuse. A literal text anchor preserves the recognized subject, negation and clause comma while replacing the old trailing hypothesis. No fuzzy matching changes a number or a negative into an affirmative. The extended source is visible in the caption.
3. **Narrow contextual short replies.** A nearby source question can select a small set of unambiguous reply senses, including declining more tea, reassuring someone after an injury question and confirming preparation. Japanese → Chinese and Chinese → Japanese are supported. Unrecognized senses use the ordinary translation path; glossary matches take precedence. Questions and replies have separate cache entries. Generated translations and conversation history are not added to the small model prompt.
4. **Bound repeated optional previews.** Repeated unchanged hypotheses gradually space optional recognition refreshes to at most a 1.1-second floor, alongside existing thermal/memory protection. New words, a new utterance or a reset clear that state. Final utterances bypass this admission policy. This can make draft refreshes less frequent; it does not delay acoustic sentence detection or discard accepted final captions.

`streaming.mjs`, VAD silence thresholds, final capture waiting and maximum capture-window settings are unchanged.

## Results and rejected experiments

The paired, alternating ASR-only probe produced identical text for all 16 clips. Median decoding time changed from **387 ms to 363 ms** (about 6%). This excludes capture, queueing, translation and UI; it is not an end-to-end speed claim.

Four paced runs, each with ten complete final translations and identical final capture positions, showed substantial timing variation under the machine's changing background load:

| Run order | Version | Median final-window-end to Chinese completion |
| --- | --- | ---: |
| 1 | 4.5.4 | 837 ms |
| 2 | Candidate | 798 ms |
| 3 | Candidate | 1,336 ms |
| 4 | 4.5.4 | 2,143 ms |

These runs do **not** establish a stable end-to-end speed improvement. The timestamp probe isolates one improvement; the paced tests establish complete output for this fixture. The candidate cut-context guard was subsequently narrowed; this fixture has no eligible sub-second final fragments, so its path is unaffected by that revision.

All 16 whole-audio results and translations match the baseline. All 16 text and eight context pattern checks pass. Selected context results improve: after an offer of another cup of tea, `もう大丈夫です。` produces `不用再加了。`; after asking whether preparations are complete, `できました。` produces `準備好了。`. Other translations can still be awkward or add an implicit subject.

Artificial-cut checks show recovered negative endings, dates, counts and subjects in several sub-second fragments. For example, a Chinese fragment previously recognized as `未来` and translated into unrelated instructions now retains `他说今天不会来。` and produces `彼は今日は来ないと言っていました。`. However, earlier incomplete cues can still misrecognize words or polarity; longer isolated endings remain imperfect. This patch does not guarantee that every cut sentence is correctly translated.

Rejected experiments are not shipped: unrestricted reference prompts sometimes translated the previous question instead of the reply; general audio overlap introduced new words; removing the overlapping text could strip negation; dropping a previously recognized comma could reverse the meaning of a later time clause. The retained approach is bounded and tested against these failures.

A 609-second production-cadence run repeated the authored audio 46 times: **92 completed final translations, zero failed finals**, and zero pending audio jobs at all 46 interval samples. There were 382 recognition calls and four uncached translation calls; repeated translations used the normal cache. The system reported `fair` thermal state throughout. Median final-window-end to Chinese completion was 941 ms, with an observed 95th-percentile sample of 2,445 ms. This is an ASR-heavy repeated-fixture stability check, not a varied live-stream or sustained uncached-translation stress test. Adaptive segmentation produced two different valid cut patterns, including a repeated fish clause across a forced boundary.

## Reproduce

From `desktop-app`, with the existing MLX environment and models available:

```sh
node scripts/prepare-speech-benchmark.mjs .test-out/speech-455
node scripts/build-speech-benchmark.cjs out/speech-benchmark-baseline e9a7d01
node scripts/build-speech-benchmark.cjs out/speech-benchmark-candidate
```

Use an isolated `COMPARE_PROFILE` with a `models` symlink to the existing model directory. Set `CORPUS_AUDIO_DIR`, `COMPARE_LABEL` and `COMPARE_REPORT`, then run the selected bundle's `quality.js` with Electron. `cuts.js` uses the same profile/audio/report variables; `COMPARE_CUT_HOLDOUT=1` selects the additional diagnostic group (the historical option name does not imply a blind evaluation).

For `paced.js`, set `COMPARE_AUDIO` to `tests/japanese-fixture.wav`, `COMPARE_ROUNDS=5` and `COMPARE_FIXED_CUES=1`. Alternate baseline/candidate order and retain capture sample positions, outputs, thermal states and background-load conditions. Omit fixed-cut mode for a production-cadence stability run. Run only one model benchmark at a time.

The MLX environment can run `scripts/benchmark-compact-asr.py AUDIO_DIR REPORT.json` for the paired decoding probe. It uses cached models only. Test audio, profiles, models and build snapshots stay outside release packages.
