# VocaLume 4.4.3 verification — 2026-10-18

## Scope

Reduce sustained optional recognition work on the user's Apple M5 MacBook Air (16 GB, macOS 26), while retaining finalized speech and its translations. Opera was deliberately left untouched at the user's request.

## Checks

- Extension: **148 passed**, including slow-decoder cooldowns, hot-worker final ordering, browser queue draining without another VAD tick, acoustic finals with previews disabled, recovery, and beta archive module dependencies.
- Desktop: **678 passed** across 72 files; type checking and production build passed. Lint: zero errors, 16 existing warnings.
- Thermal policy: immediate escalation, severe speed-limit handling, critical preview suspension, invalid sample rejection, and gradual 30-second recovery.
- Installed `/Applications/VocaLume.app` 4.4.3 after checking its built-runtime bytes, renderer assets, portable native addon and local deep signature. The prior 4.4.2 app was retained as a temporary backup; existing settings and models were retained.
- Six real installed native-transport operations passed: Japanese-to-Chinese text, Chinese-to-Japanese text, initialization, provisional recognition, complete paired caption, and stop. The real fair thermal state returned the new 0.65 preview duty setting. The short-window hypothesis remained provisional; these transport checks do not establish translation accuracy for arbitrary speech or writing.
- Real MLX Whisper + HY-MT1.5 1.8B Q4 inference on the existing Japanese fixture, twice per build. Engines were warmed before timing. The scheduling policy was injected as serious; the real OS state reported **fair**. This does not mean the machine was physically driven to serious thermal pressure.

## Local comparison

The separate comparison runs had no concurrent build/test processes. Other user applications remained open. The baseline used `c6b9f1a`; the changed build used the same models and fixture. [Raw measurements and fixture hash](4.4.3-local-processing.json).

| Measurement | Before | After |
| --- | ---: | ---: |
| Optional recognition calls | 11 | 7 |
| Repeated audio submitted for optional recognition | 56.0 s | 33.5 s |
| Time inside optional recognition calls | 16,035 ms | 12,436 ms |
| Completed recognition / Chinese translation pairs | 2 / 2 | 2 / 2 |
| All recognition call time | 18,502 ms | 17,636 ms |
| Total test wall time | 31,770 ms | 36,030 ms |

Both full Japanese results and both Chinese translations were identical between the two builds. These are repetitions of one short fixture, not an accuracy benchmark. Fewer preview calls and less repeated input demonstrate the intended workload reduction. Total wall time **did not improve** in this sample; no claim of lower end-to-end latency is made. Decode duration varied substantially, including a slower final decode in the changed run.

An earlier comparison overlapped other checks and is excluded from the table. One desktop socket test hit its five-second deadline during concurrent model/check activity; the full suite subsequently passed twice without that contention. No production behavior was changed to hide the timeout.

## Remaining limits

- No long livestream thermal soak, wattage measurement, or temperature sensor trace was performed. Xcode Instruments was unavailable on this machine.
- The scheduling work/idle ratio applies to optional recognition admission, not total device utilization. Completed sentences bypass that cooldown.
- Critical pressure can suppress live source drafts until a sentence is finalized. Warm pressure also pauses optional extra draft recognition and preview speaker analysis.
- No guarantee of preventing physical heat or OS throttling. See [the behavior guide](../thermal-performance.md).
- Browser UI reload and live Opera testing remain deferred at the user's request. Updating the source folder does not reload an existing extension worker or page content script.
