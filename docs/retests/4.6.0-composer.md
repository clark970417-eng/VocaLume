# Reply editor synchronization and retry controls

Date: 2026-10-27. This is an unreleased extension correction on top of 4.6.0.

## Problem and change

The social adapter previously fell back to replacing a contenteditable element's `textContent`. A framework-owned editor could display Japanese while keeping Chinese in its submission state. Discord/Twitch drafts now use an editor-handled replacement or plain-text paste event; React textareas use the native value setter and input notification. There is no direct-DOM replacement fallback for managed editors. If insertion cannot be confirmed, a selectable draft and recovery instructions remain visible.

The operation preserves line breaks and emoji, waits for the framework's render before confirming success, and does not dispatch a send click, submit event or Enter key. Active IME composition and later source edits prevent replacement. Read-only fallback drafts cannot become translation targets themselves.

Discord/Twitch controls reserve a separate row before the native composer. A portal fallback measures the composer and Send row and positions outside them; resize and scroll refresh its position. Page/chat retry buttons have consistent pill styling, a refresh icon, hover feedback and visible keyboard focus.

The framework transaction follows [Slate's native beforeinput and paste handlers](https://github.com/ianstormtaylor/slate/blob/main/packages/slate-react/src/components/editable.tsx). Actual deployed site versions can differ from upstream.
