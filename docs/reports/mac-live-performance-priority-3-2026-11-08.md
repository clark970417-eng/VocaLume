# VocaLume Mac 第三階段效能驗證

在同一部 Apple M5、16 GB、macOS 26.4.1 的 Mac 上重跑。使用同一份 135.088 秒日文音檔、Haas-ja Q8_0、HY-MT1.5 1.8B Q4_K_M、800 毫秒收音設定、原有 VAD 斷句時間和十筆同時執行的桌面文字翻譯。基準版是已完成第二階段的本機版本。四輪均使用電池，低耗電模式關閉，macOS 熱狀態全程正常。正式相鄰對照依序跑新版、基準版。

## Retina 字幕樣式

以 Electron GPU 合成的離屏點陣圖跑四種字幕樣式。內建螢幕縮放倍率 2，輸出 1470 × 400 像素，以約 30 fps 的動畫背景重用 20 組字幕。每種樣式跑兩次，第二次反轉順序。每次取 5 筆 AGX 樣本並輸出 102–103 幀。全程熱狀態正常。

| 樣式 | 整機 GPU Device Utilization 平均／範圍 | Electron GPU 程序 CPU 平均 |
| --- | ---: | ---: |
| 不透明 | 2.8%／0–11% | 0.70% |
| 半透明 | 6.1%／0–11% | 0.70% |
| 半透明加模糊 | 7.5%／0–12% | 0.86% |
| 半透明加模糊和陰影 | 4.8%／0–12% | 0.83% |

各組讀值範圍重疊，平均值也未隨效果數量遞增。離屏點陣圖另有影像複製，未經實體畫面輸出。這個短測無法單獨證明哪一種效果降低 GPU 負載或溫度。 [Electron 離屏渲染](https://www.electronjs.org/docs/latest/tutorial/offscreen-rendering)

## OBS 字幕檔與實際渲染

用相同 21.821 秒音檔在兩個建置產生正式雙語字幕。將測試字幕檔接到本機 OBS 33.0.1 的 libobs Metal 合成器及內建 Text (FreeType 2)，輸出 640 × 360、30 fps，讀取合成畫格的像素。這個隔離測試驗證 OBS 實際渲染，未擷取實體預覽視窗或開始推流。 [OBS 文字來源](https://obsproject.com/kb/text-sources)

| 指標 | 修改前 | 修改後 |
| --- | ---: | ---: |
| 正式雙語字幕渲染 | 3／3 | 3／3 |
| App 字幕檔寫入（逐筆） | 1／1／2 ms | 5／2／1 ms |
| 檔案事件至 OBS 第一張更新畫格（逐筆） | 1,462／1,142／1,594 ms | 1,987／1,616／2,025 ms |
| 按停止至字幕檔清空 | 60 ms | 64 ms |
| 檔案清空至 OBS 第一張空白畫格 | 1,604 ms | 1,664 ms |

兩輪三張對應字幕畫格的像素雜湊逐一相同，停止後都出現空白畫格。實測中 OBS 讀檔至畫格更新占主要等待，三筆資料不足以判定渲染變快或變慢。App 改為略過相同的連續正式字幕，驗證內容變更、清空、關閉及寫入失敗後重試仍正常。Electron 端對端測試另確認「只輸出到 OBS」會停止桌面字幕視窗，停用後可恢復。

前置測試用暫存設定啟動 OBS 一般介面時，OBS 預設初始化了麥克風並提出虛擬攝影機更新。macOS 拒絕該更新，測試程序隨即關閉，未開始錄影或推流。上表改用只載入內建文字來源的隔離渲染程序。

## 背景工作與驗證

- 擴充功能的網頁變更測試確認，同一批變更只掃新增子樹和受影響的既有區塊。測試中全頁查詢 0 次，同時新增父子節點只掃 1 次。自身字幕或狀態的變更不會啟動掃描。
- Mac 新版在此輪成功啟動記憶體壓力通知程式。另驗證通知程式能回報初始狀態，關閉輸入後正常退出。實際對照保留作業系統的正常及警告取樣，未主動施加記憶體壓力。 [Apple 記憶體壓力通知](https://developer.apple.com/documentation/dispatch/dispatchsourcememorypressure)
- 桌面測試 971 項、擴充功能測試 340 項、Chrome 隔離撰寫框測試 33 項與 Electron 的 OBS-only 測試 1 項通過，桌面型別檢查通過。
