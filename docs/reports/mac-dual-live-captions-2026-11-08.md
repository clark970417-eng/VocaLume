# Mac 雙直播字幕實測（2026-11-08）

在 16 GB Apple Silicon Mac 上，用兩個獨立的 Chrome for Testing 個人資料同時擷取不同的公開 Twitch 直播。使用擴充功能的瀏覽器模式、單組字幕、Whisper Small FP32、日本語 → 繁體中文及預設網路文字翻譯。每路的語音辨識在本機執行。測試未更換辨識模型或調整斷句等待。

公開直播：[fps_shaka](https://www.twitch.tv/fps_shaka) · [k4sen](https://www.twitch.tv/k4sen)

## 同音訊重播

在真實直播雙路收音後，各取約 121 秒音訊。用相同檔案、已快取的同一模型、相同設定和兩個獨立瀏覽器個人資料重播。兩組輸入檔案雜湊一致。比較 `beta-v4.6.7` 與效能候選版 `2dd06d5`，每輪觀察 120 秒。秒數以各輪收到正式譯文的字幕計算。

| 指標 | fps_shaka 4.6.7 → 效能候選 | k4sen 4.6.7 → 效能候選 |
| --- | ---: | ---: |
| 播放至首筆正式譯文 | 11.70 → 7.88 秒 | 12.09 → 9.17 秒 |
| 句尾至正式譯文 P50 | 3.66 → 3.42 秒 | 3.18 → 3.00 秒 |
| 句尾至正式譯文 P95 | 7.42 → 5.78 秒 | 6.28 → 5.01 秒 |
| 正式原文至譯文 P95（含排隊） | 3.94 → 1.96 秒 | 2.80 → 2.13 秒 |
| 送出的網路翻譯請求 | 28 → 10 | 81 → 21 |
| 正式譯文送往字幕畫面／正式辨識輸出 | 9/10 → 9/10 | 14/19 → 19/20 |

此次測到的斷句尾端等待 P95 都是 1.408 秒。基準版會把多個暫定原文送去翻譯，和正式譯文爭用請求。更新後暫定文字仍可顯示，只有辨識已確認的暫定結果和正式原文送翻譯，正式請求優先。收音積壓時會批次處理已入列的音訊，日文逐字預覽也少做重複解碼。模型已載入後的首次推論仍可能偏慢，重播基準其中一路的首次辨識約 7.4 秒。首次模型下載與載入在不同輪次約 96 至 267 秒，另行計算。

## 最終修正版的公開直播短測

中間版本仍出現翻譯服務逾時，以及較新的譯文提早回來、較舊的正式譯文被略過。最終版 `20d65dc` 讓瀏覽器模式的正式譯文依原文順序送出，保留並行翻譯。獨立瀏覽器使用預設翻譯服務時，逾時的正式譯文最多再試一次。未新增翻譯服務或改動收音等待。

- 約 4 分鐘的雙路觀察中，兩場直播持續播放，六次上游 5xx 或逾時均有後續結果。停止第一路後，該路字幕清空，第二路仍送出新譯文。
- 正式譯文比率以辨識器已輸出的正式原文為分母，統計送往字幕畫面的事件。畫面採抽樣檢查，重複文字和快速相鄰的更新可能少算。這個比率無法涵蓋未被辨識的語音或譯文語意準確度。
